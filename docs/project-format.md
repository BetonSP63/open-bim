# Открытый формат проекта v1

Расширение `.obim`, UTF-8 JSON. Заголовок `magic: "open-bim-project"`, `format_version: 1`, `payload_sha256` и объект `project`. Поля модели, ID, единицы, каталоги, локальные базисы и свойства описаны в docs/model.md. Неизвестные поля основной структуры отвергаются.

Контрольная сумма SHA-256 считается от результата `Project::to_json`: pretty JSON с порядком полей Rust struct и упорядоченными BTreeMap. Алгоритм не зависит от пробелов внешней envelope; Unicode сохраняется в UTF-8. Другие реализации должны следовать каноническому payload-представлению либо пересериализовать известную схему с таким же порядком/форматированием чисел. Fixtures задают точный эталон текущей версии. Изменение этой канонизации требует новой версии формата.

Версия 0 — предыдущая envelope с `magic`, `format_version: 0` и `project`, без контрольной суммы. Миграция выполняет полную валидацию и только в памяти добавляет envelope v1; исходный файл не перезаписывается. Это специально зафиксированный начальный legacy-формат, не формат сторонних программ.

## Сохранение

Модель сначала валидируется и сериализуется. Файл с уникальным именем создаётся рядом с назначением, записывается и sync_all. После этого rename заменяет целевой файл атомарно, затем sync_all каталога подтверждает метаданные. До rename любой сбой оставляет прежние байты; временный файл убирается. Если ошибка синхронизации каталога возникла после rename, новый файл уже может быть виден — это явно ошибка подтверждения долговечности, не откат коммита. Тестовые точки сбоя ограничены стадиями до rename.

## Автосохранение

`.obima`: 8 байт `OBIMAUTO`, затем последовательность записей: длина payload u64 little-endian; 32 байта SHA-256 payload; payload envelope `.obim`; 8 байт `COMMIT1\n`. Запись создаётся после завершённой транзакции и sync_all до подтверждения сохранения. Межпроцессная блокировка файла защищает от смешивания записей.

Восстановление читает только полные записи с верными checksum/commit-маркерами. Незавершённый хвост возвращается отдельным числом discarded_tail_bytes, последнее полное состояние восстанавливается. Существующий журнал при чтении не меняется. Повреждение завершённой записи — ошибка, не молчаливое пропускание. После восстановления с хвостом нужно начать новый журнал или явно сохранить восстановленный проект в новый файл.

Пределы: проект 256 MiB, журнал 1 GiB, модель до 1 млн ID, карты до 1 млн записей. Чтение ограничено до выделения большой памяти; serde ограничивает глубину JSON. Все ошибки имеют читаемый текст. Неизвестная версия требует обновлённого reader, исходный файл сохраняется.

Тесты проверяют Unicode и пробелы в пути, миграцию legacy-v0, checksum, чрезмерный размер, инъекции трёх сбоев и восстановление после настоящего kill дочернего процесса.
