# Архитектура

Единицы домена — миллиметры, вычисления — f64. GUI не определяет геометрическую точность. GPU использует локальное начало координат и f32 только после подготовки отображения.

## Слои и направление зависимостей

| Слой | Назначение | Допустимые зависимости |
|---|---|---|
| geometry | точные тела, кривые, топология, допуски | выбранное CAD-ядро |
| model | ID, элементы, свойства, сборки, каталог | geometry |
| commands | транзакции, отмена, события изменений | model |
| persistence | открытый формат, миграции, атомарная запись | model |
| renderer | tessellation, камера, GPU, picking | model, geometry, wgpu |
| drawings | виды, размеры, ссылки на модель | model, geometry |
| exchange | IFC/DXF и диагностика покрытия | model, geometry |
| desktop | русский интерфейс и маршрутизация команд | остальные слои |

На этапе 1 созданы geometry, model и desktop. Остальные слои создаются при реализации своих функций, без фиктивных API. Для IFC/DXF могут использоваться отдельные crate в слое exchange.

## Инварианты
- ID сохраняется при редактировании, нумерации и сохранении.
- Изменение модели проходит через транзакцию; ошибочный ввод не оставляет частичного изменения.
- Кэши рендера, чертежи и позиции обновляются по событию изменения.
- Повреждённая геометрия и неподдерживаемый импорт имеют явную ошибку, а не приближённый успех.
- Библиотека model не импортирует GUI/GPU; cargo tree используется для проверки границы.
- Выбор CAD-ядра закрепляется только после независимых аналитических проверок этапа 2.

Формат проекта, граф зависимостей и схема чертежей документируются вместе с реализацией; нынешняя архитектура не является свидетельством готовности этих функций.
