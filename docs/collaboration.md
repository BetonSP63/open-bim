# Совместная работа над одной моделью

Версия 1.0: несколько инженеров ведут одну модель через **общую папку** с
блокировками. Сервер не нужен. Сервер с мгновенными уведомлениями — версия 1.1.

## Как это выглядит для инженера

1. Ведущий инженер выбирает «Совместная работа → Создать общую модель» и
   указывает пустую папку на сетевом диске. Текущая модель становится ревизией 1.
2. Остальные выбирают «Открыть общую модель». Программа берёт последнюю
   ревизию и держит у себя локальную копию; работать можно и без сети.
3. Перед изменением объекта программа **занимает** его. Занятый другим
   объект нельзя изменить: программа отменяет такую правку и пишет, кто его
   занял и с какого времени. Занятые объекты видны в модели цветом и в
   списке «Кто что занял».
4. «Сохранить в общую модель» (Ctrl+Shift+S) записывает новую ревизию с
   комментарием. Изменения других инженеров, сохранённые за это время, не
   теряются: модели объединяются по объектам.
5. «Получить изменения» приносит чужие ревизии в локальную копию, не трогая
   несохранённую работу.
6. «Освободить» отдаёт занятые объекты. По умолчанию они освобождаются при
   сохранении в общую модель.
7. Нумерация меняет марки всей модели, поэтому её может запускать только тот,
   кто занял поле «нумерация».

## Устройство папки

```
<папка>/
  shared.json            заголовок: сигнатура, версия формата, последняя ревизия
  history/000001.obim    модель каждой ревизии (формат .obim, не меняется)
  history/000001.json    автор, время, комментарий, что изменено
  locks/save.lock        короткая блокировка на время одного сохранения
  locks/objects/*.lock   блокировки объектов и полей: кто и когда занял
  ids/<k>.json           диапазон ID k·2³² … (k+1)·2³² и кому он выдан
```

Нужны только две гарантии файловой системы: создание файла «только если его
нет» и атомарное переименование. Их дают локальные диски и сетевые папки
SMB/NFS. **Папки облачной синхронизации не подходят**: они копируют файлы
с задержкой и не умеют исключительное создание.

Файлы истории пишутся один раз; `shared.json` заменяется последним, поэтому
читающий всегда видит законченную ревизию, даже если сохранение прервалось.

## Единицы слияния и блокировки

Модель делится на единицы:

- каждая запись карт объектов — деталь, сборка, ось, уровень, узел, чертёж,
  размер, плагин, экземпляр семейства, материал, профиль; параметры
  гнутой/протянутой детали идут вместе с её деталью;
- каждое семейство по имени;
- каждое прочее поле проекта целиком: основная надпись, изменения, сетка,
  виды, управление, анализ, параметры, бетонирование, формы, сечения,
  нумерация, название.

Блокировка называется по единице: `id-12`, `family-<имя в hex>`,
`field-grid`. Новое поле проекта автоматически становится отдельной единицей,
поэтому слияние ничего не теряет, даже если о поле здесь не написано.

## Сохранение в общую модель

1. Занять `locks/save.lock` (ждать до 30 с, пока сохраняет другой; блокировку
   старше 10 минут оставила упавшая программа — её можно забрать).
2. Прочитать последнюю ревизию и объединить три версии: базу (ревизию, с
   которой начата локальная копия), свою копию и общую.
   - Изменено только у одного — берётся его вариант.
   - Изменено у обоих по-разному — **конфликт**. Программа показывает
     список и для каждой единицы предлагает «оставить моё» или «принять
     общее». Блокировки делают конфликт редким: он возможен, только если
     объект меняли, не заняв его.
3. Проверить, что отправляемые единицы не заняты другими.
4. Проверить объединённую модель целиком (`Project::validate`). Например,
   если один удалил деталь, а другой включил её в сборку, сохранение
   отклоняется с понятным текстом.
5. Записать ревизию N+1, освободить `save.lock`.

## Занятие объекта

Занять можно, только если объект в общей модели не менялся после базы
локальной копии. Иначе программа просит сначала получить изменения — так
никто не перезапишет чужую правку устаревшей копией.

Программа узнаёт, что меняет команда, сравнивая модель до и после команды
(`changed_units`). Поэтому проверка работает для всех команд сразу, без
разметки каждой.

Чужую блокировку инженера, который ушёл и не освободил объекты, можно снять
командой «Снять чужую блокировку» после подтверждения (`force_release`).

## Диапазоны ID

Каждый инженер при подключении получает свой диапазон из 2³² ID
(`ids/<k>.json`, создание «только если нет»), поэтому новые объекты двух
инженеров никогда не получают одинаковые ID. Модель одного инженера
по-прежнему живёт в первом диапазоне. Проверка модели требует свободных ID
выше счётчика только в диапазоне самого счётчика: объекты из чужих диапазонов
могут иметь ID больше него.
