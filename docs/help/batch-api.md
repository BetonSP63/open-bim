# Пакетный режим и программный интерфейс модели

Модель можно менять без окна программы: макросом JSON через
`open-bim-batch` или из кода Rust через крейт `open-bim-api`. Это основа для
макросов, автоматизации типовых работ и будущих расширений.

## Три отдельных шага

1. **Объект — просто данные.** Значения балки (точки, профиль, сталь) ничего
   не меняют в модели, пока не вызвана операция.
2. **Вставка, изменение, удаление** проверяют объект (точки не совпадают,
   профиль и сталь есть в модели или в каталоге, контур пластины плоский) и
   ставят изменение в очередь сеанса. Выборки уже видят его.
3. **Фиксация** (`commit`) превращает всю очередь в один шаг отмены: узлы
   перестраиваются, вся модель проверяется. **Откат** (`rollback`) очищает
   очередь. **Сохранение** и экспорт работают только с зафиксированной
   моделью и отказываются, пока в очереди есть изменения.

Профили и стали, которых нет в модели, берутся из встроенного каталога
ГОСТ по имени: `"30Б1 (Р 57837)"`, `"Гн 150×100×6"`, `"С255"`.

## Макрос

```json
{
  "open": "frame.obim",
  "steps": [
    { "insert_member": { "profile": "30Б1 (Р 57837)", "material": "С255",
                         "start": [0, 0, 3000], "end": [6000, 0, 3000] } },
    { "copy": { "vector": [0, 6000, 0], "count": 3 } },
    { "commit": "Балки перекрытия" },
    { "select": { "kinds": ["column"], "touching": { "min": [-100, -100, 0], "max": [100, 100, 4000] } } },
    { "set_property": { "key": "этап", "value": { "type": "text", "value": "1" } } },
    { "commit": "Этап колонн" },
    { "export_ifc": "frame.ifc" },
    { "export_nc": "nc" },
    { "export_reports": "reports" },
    { "save": null }
  ]
}
```

Запуск: `open-bim-batch макрос.json`. Отчёт о шагах (новые ID, ревизии,
пути файлов) печатается в JSON. При ошибке выполнение останавливается и
печатается номер шага; незафиксированные изменения не сохраняются. Пути
считаются от папки макроса. Без `"open"` создаётся новая модель.

### Шаги

| Шаг | Что делает |
|---|---|
| `insert_member` | балка или колонна: `kind` (`beam`/`column`), `name`, `profile`, `material`, `start`, `end`, `position` (положение детали), `properties` |
| `insert_plate` | пластина: `material`, `thickness`, `outline` — точки контура в мировых координатах; деталь откладывается по нормали контура (правило правой руки) |
| `modify_member`, `modify_plate` | то же с `id`; ID сохраняется |
| `select` | выборка: `kinds`, `name`, `profile`, `material`, `property` `[имя, значение]`, `inside` (габарит детали целиком в рамке), `touching` (касается рамки) |
| `delete` | удаление; `cascade: true` удаляет и зависимые объекты |
| `set_property` | пользовательское свойство; без `value` — удалить |
| `move` | перенос на `vector` |
| `copy` | `count` копий, каждая смещена на `vector` от предыдущей |
| `commit`, `rollback`, `undo` | фиксация с подписью, откат очереди, отмена последней фиксации |
| `save` | сохранить в файл или обратно в открытый (`null`) |
| `export_ifc`, `export_nc`, `export_reports` | IFC; папка `.nc1` по маркам; папка CSV-спецификаций (детали, сборки, крепёж) |

Шаги с объектами действуют на **текущий выбор**: результат последней
вставки, копирования или `select`. Другую цель задаёт `target`:
`{ "ids": [12, 13] }` или `{ "query": { … } }`.

Детали, созданные узлами, не переносятся и не копируются напрямую:
перемещайте основные детали, узел перестроится при фиксации.

## Чертежи

Чертёж создаётся по **типу**: деталь (`part`), сборка (`assembly`), общий
вид (`general`, список деталей или пусто — вся модель) или «Общие данные»
(`general_data`: `"КМД"` или `"КМ"`). Виды строит движок чертежей;
обозначение по умолчанию — «КМД-<марка>».

Правила открытого чертежа:

- оформление листа (обозначение, наименование, формат, масштаб, примечания)
  меняется только у **открытого** чертежа;
- открыт может быть один чертёж; пока он открыт, нельзя создать или открыть
  другой, удалить, обновить или выдать его самого и отменить фиксацию;
- `close_drawing: true` ставит все правки чертежа в очередь одной заменой,
  `false` их отбрасывает; дальше, как обычно, `commit`;
- обновление по модели и выдача работают с закрытыми чертежами, как в
  менеджере документов. Выдать можно только актуальный чертёж.

| Шаг | Что делает |
|---|---|
| `create_drawing` | `{ "part": 10 }`, `{ "assembly": 20 }`, `{ "general": [] }` или `{ "general_data": "КМД" }`, плюс необязательный `number` |
| `create_drawings` | мастер чертежей: `assemblies`, `parts`, `part_rule` (`all`, `plates`, `secondary`), `general_data`, `only` (ID деталей) |
| `open_drawing` | открыть чертёж по ID; `null` — последний созданный в макросе |
| `edit_drawing` | `number`, `title`, `sheet` (`a4`…`a0`), `scale` (ряд ГОСТ 2.302), `notes` (`text`, `position` в мм листа, `height`) |
| `close_drawing` | `true` — сохранить правки, `false` — отбросить |
| `delete_drawing` | удалить чертёж по ID |
| `update_drawings` | обновить по модели (`[]` — все устаревшие) |
| `issue_drawings` | выдать (`[]` — все актуальные и ещё не выданные) |
| `export_pdf` | `path` и `drawings` (`[]` или нет — все): один PDF |
| `export_dxf` | `dir` и `drawings`: DXF на каждый чертёж, имя по обозначению |

```json
{ "open": "frame.obim",
  "steps": [
    { "create_drawings": { "part_rule": "plates" } },
    { "commit": "Чертежи пластин" },
    { "update_drawings": [] },
    { "issue_drawings": [] },
    { "commit": "Выдача" },
    { "export_pdf": { "path": "КМД.pdf" } },
    { "save": null } ] }
```

## Плагины

Шаг `run_plugin` запускает плагин — отдельную программу, которая отвечает
шагами макроса. Описание, протокол и пример: `docs/help/plugins.md`.

## Из кода Rust

```rust
let mut s = open_bim_api::Session::open("frame.obim")?;
let mut beam = open_bim_api::Member { /* … */ };
let id = s.insert_member(&mut beam)?;
s.copy_by(&[id], [0., 6000., 0.])?;
s.commit("Балки")?;
s.save(None)?;
```

`move_between` и `copy_between` переносят детали из одной системы
координат в другую (поворот и смещение одним действием).
